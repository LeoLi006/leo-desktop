## 本轮确认并修复

1. 原代理与媒体共用一个配置戳，任一变化会重建二者并清空媒体目标。改为两个独立戳，队列保持各自所有权。
2. FootballQueries.Suspend/Dispose 原在锁内调用 Cancel；提供者回调可能重入或阻塞。先在锁内切代/标记关闭，再在锁外取消，并确保释放令牌源。
3. Launcher 指令没有生命周期令牌和执行中保护。现同一窗口执行中拒绝重复提交，销毁取消；忽略取消的晚到结果不会再碰界面。普通隐藏仍保持原使用语义。
4. 宿主及搜索框释放过程原为连续调用，单模块抛错会跳过后续清理。现逐项隔离可恢复异常，取消失败也继续释放其余资源；不吞致命运行时异常。清理错误只记录异常类型，避免退出中弹窗。

## 清理与兼容结论

- 删除了耦合代理/媒体的旧合并配置戳与整组提前返回分支，替换为独立配置判断。
- 未发现足够证据可以删除整个 ClientOperationHub：外部扩展仍使用；QQPlayback.ToggleAsync/SetPausedAsync 仍由 --qq-pause-send 诊断入口调用，保留。
- LeoActions、ModuleCatalog、旧动作适配和拒绝旁路的保护分支仍有兼容用途，保留。UI读取不可变快照不属于重复写入入口。
- 宿主动画、热键、通知、主题、窗口定位属于宿主服务；本轮不把它们伪装成已独立交付的业务模块。不改个人数据格式、旧动作编号或发布版本。
