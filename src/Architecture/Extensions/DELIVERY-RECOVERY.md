# 交付与配置联合恢复核验

日期：2026-10-21；源码基线b947e75（运行逻辑基线abb6992）。范围为一项隔离数据型应用包与一个仓库声明式LeoModule/1扩展，沿用原执行器、方案、状态和入口，不新增用户业务。

## 联合路径与范围

夹具使用真实ApplicationPackages、ExtensionStore、UsageProfiles、ProfileTransition、AtomicJson、注册表/分发器和LauncherForm；应用Host的准备/启动是可控模拟器，假EXE仅文本，绝不执行。声明式扩展固定指向已有local_app_open，值为隔离应用编号，不使用stdio或第三方程序。

顺序覆盖：应用草稿→保存生效→扩展安装及真实快捷控件→扩展动作转交应用→方案捕获/导出/重新导入→应用与扩展更新→部分停用及纯桌宠方案→恢复方案→请求取消/重复点击→从隔离文件重建宿主→移除→再次加载→显式重装。测试按宿主规则显式取消/刷新，不假设Register自动处理全部生命周期。

配置发布模拟宿主的“先保存，再发布到活动偏好并刷新”，只复制隔离对象；这不是完整PetForm设置应用端到端测试。重新加载指读取隔离文件、构造新分发器与绑定，不关闭真实Leo或重启Windows。无任何实际程序就绪/播放/代理效果保证。

## 初次复现与最小修复

首轮25项中1项失败：应用已停用时，扩展执行会正确拒绝启动，但扩展状态仍显示检查通过。ExtensionLeoModule.ReadDependencies只查询local_app_open这个通用核心动作是否启用，没有按固定Value解析实际应用。

只增加TargetReady的被动目标解析，复用分发器既有的local_app_open→local:<应用编号>归一规则；目标必须启用，并通过既有应用文件/工作目录依赖检查。目标移除或格式无效走原异常隔离，返回extension-target缺失。其他声明式目标及stdio路径保留原规则，不递归调用业务或任意网络检查，不修复路径、不准备/启动程序，不增加模型工具或执行权限。

因此这一修复改变的是依赖摘要的真实性，原执行拒绝规则保持。扩展入口不因此获得绕过应用停用的权限；入口隐藏与模块停用仍分开，状态未通过不等于删除安装包。

## 故障与恢复语义

| 联合处 | 证据及限制 |
| --- | --- |
| 应用包升级保存失败 | 活动配置、磁盘原文件及状态版本保持；成功提交后才显示新版，不因读取状态启动程序 |
| 扩展JSON更新失败 | 原声明与入口保持；成功更新后状态版本与真实快捷控件名称刷新。ZIP恢复采用上一批证据，本轮不重测ZIP或worker |
| 方案切换保存失败 | 保存前失败不发布新配置；恢复保存若也被注入拒绝会明确失败，原磁盘与活动视图仍保留。本轮不把双重失败说成恢复成功 |
| 停用与恢复 | 纯桌宠方案隐藏两者入口而保留包/配置；恢复原方案只改变开关/显示，不把包版本退回捕获时的旧版本 |
| 取消与重复请求 | 在模拟启动提交前取消不产生效果；在途相同扩展点击合并为一次模拟启动。不是完成后任意重复点击的永久幂等保证 |
| 重新加载 | 新分发器从文件恢复身份、版本、状态及入口，不自动重放动作；检查前保留启动计数作为对照 |
| 移除与重装 | 移除扩展清理真实控件并拒绝旧身份点击；应用移除保留原绑定墓碑/本机配置。重新加载仍保持移除，module-data不删除；仅显式重装恢复入口，不自动执行 |

这里没有跨配置文件与扩展目录的原子总事务、跨进程/断电恢复器或新的补偿规则。各自提交成功的步骤仍可能已生效，不把取消解释为回滚一切。未测真实个人配置、系统重启、外部客户端成功率或长期负载。
