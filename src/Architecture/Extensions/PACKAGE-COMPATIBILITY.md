# D02/D03：旧扩展包兼容检查与更新恢复

日期：2026-10-21；基线11ba1de。仅扩充现有LeoModule/1声明与安装事务；不改变旧动作编号、口令、安装目录、stdio执行器或模型权限。

## 可选声明

JSON模块及ZIP中的module.json均可省略新字段；省略表示不限制宿主版本、无额外声明依赖。旧包不需要重打包。

```json
{
  "Format": "LeoModule/1",
  "Id": "daily-plan",
  "Name": "每日计划",
  "Version": "1.1.0",
  "HostMin": "1.4.0",
  "HostMax": "1.4.99",
  "Dependencies": ["windows", "leo-module/1", "leo-host-contract/1"],
  "Commands": [
    { "Id": "today", "Title": "今日计划", "Phrases": [], "Action": "todos_open" }
  ]
}
```

- HostMin、HostMax采用.NET数值版本，闭区间；缺少的build/revision补零。比较当前宿主程序集版本，不按文本或Git提交比较。不支持SemVer预发布/通配符/表达式，倒置或非法范围直接拒绝。
- Dependencies最多16个、不重复、每项最多80字符。当前被动支持windows、leo-module/1、leo-host-contract/1、stdio/v1，以及module:<已安装模块ID>。未知声明视为不可用，绝不自动下载、启动依赖或修改系统。
- module依赖要求目标存在、未停用且其宿主范围及递归声明也可用；缺失、循环或不兼容均不可用。这不是依赖版本求解器、启动顺序调度或动态协议协商。
- 安装入口先做格式及本机兼容检查，再确认安装；真正写入前重新检查。ModulePackage.Inspect仍只负责ZIP格式与内容，调用者导入时必须用ExtensionStore.InspectPackage/InstallPackage。
- 手动复制到安装目录的不兼容包保留在原管理窗口供查看/移除，但执行与入口可用性受阻。原管理列表显示不可用，详情显示范围和依赖原因，长内容可滚动。执行时仍检查程序存在及原目标状态。

## 更新事务与数据边界

| 阶段 | 行为及失败处理 |
| --- | --- |
| 检查 | 原版本递增、运行中更新拒绝、路径/ZIP限制保留；不兼容先拒绝，不修改旧包 |
| JSON声明 | 沿用AtomicJson原子替换与备份；写入失败保留原声明 |
| ZIP暂存 | 解压到模块根目录内.install-随机标识；重新校验暂存声明与预览一致及程序存在；失败清理暂存、不动旧包 |
| 切换 | 旧目录移到.previous-随机标识，再提升暂存目录；提升失败把旧目录移回 |
| 双重失败 | 如果恢复本身也被文件系统拒绝，明确报告自动恢复未完成，保留旧目录供关闭Leo后恢复；不谎报仍可执行或更新成功 |
| 清理 | 提升成功后才清理旧目录；清理失败作为成功附带警告，不把已经生效的更新当成失败。部分删除后的残留不保证仍是完整备份 |

所有移动/递归删除前核验绝对路径在原模块根目录内；沿用禁止模块链接目录及包内路径检查。个人配置、EntryDisplayModes、启停设置与根目录旁的module-data不属于包替换范围；卸载保留module-data。包目录内未经约定放入的个人文件不承诺保留，模块应使用既有独立数据目录。

这是同卷目录切换及异常回退，不是跨进程/断电事务、签名认证、执行权限沙箱或完全自动恢复器；没有自动数据迁移与任意第三方程序可信保证。隐藏保留目录不作为已安装模块加载，不自动删除双重失败留下的恢复材料。
