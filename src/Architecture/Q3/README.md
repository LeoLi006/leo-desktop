# Q3：便签数据模块试点

批准范围：迁移便签保存、查询和窗口入口；沉淀数据、窗口、反馈服务；验证并发、取消、重试及旧入口兼容。资源只要求没有明显退步，不做反复微调。本批不迁移清单、足球或音乐业务，不新增开关或改变界面布局，不制作发布包、不更新 GitHub 发布材料、不上传。

## 1. 已完成的闭环

| 层次 | 实现 | 责任 |
| --- | --- | --- |
| 注册 | `CapabilityRegistry.Register` | 注册宿主内模块；从旧内置适配器移除已被替换的动作，旧动作只归属于一个执行器；缓存替换后的内置快照 |
| 模块 | `NotesCapability` | 定义便签动作、输入适配、串行数据访问、成功回放、错误码和窗口调用 |
| 数据服务 | `ModuleJsonData<T>` | 按存储实例锁定、复制编辑、原子写盘、成功后发布新内存快照；继续使用现有备份恢复规则 |
| 窗口服务 | `ModuleWindowService` | 回到宿主 UI 线程；取消或宿主销毁后不执行排队的显示回调 |
| 反馈服务 | `ModulePresentationFeedback`（C04统一窗口服务，已替代早期反馈适配器） | 成功默认安静，失败可报告；仅明确需要时确认成功，不新增通知链路 |
| UI 适配 | `NotesClient` | 现有便签编辑器和速记窗口经统一分发器保存、查询、置顶、删除和关联；保留同步保存及关闭确认的语义 |
| 兼容入口 | 菜单、热键、拖放、搜索、聊天、语音、组合 | 原 `notes_open` / `note_add` 动作及本地口令继续工作 |

便签仍是核心记录能力，没有引入独立停用开关。模块的窗口实例由现有宿主持有，沿用位置记忆和关闭规则；不是另建窗口管理器。

## 2. 执行及取消规则

- `serialized-store` 不按文字相同合并请求。便签模块串行处理同一实例的数据操作；存储本身也保护读写，外部获取列表时得到副本。独立的两次“记下相同文字”仍是两次用户操作。
- 数据工作按需在线程池执行，没有新增轮询、计时器或常驻工作线程。编辑器仍等待短时本地保存完成再离开，避免改掉原有未保存提示语义；不宣称慢磁盘时界面完全无等待。
- 取消由请求持有，排队请求在进入数据操作和原子写盘前检查取消。最后一个订阅者取消、期限到达或宿主退出，会停止后续工作。
- 已进入不可中断的原子替换不会强行撤销。取消反馈明确提示已提交操作可能生效，不宣称回滚；确认保存状态后再操作。
- 不自动重试。模块在当前运行期间最多保留最近 128 个成功写请求的回放结果；相同请求 ID 与相同内容返回原结果，相同 ID 换内容拒绝。便签编辑器失败后重试同一新草稿会复用请求 ID。
- 回放不写入个人 JSON，**不是跨进程重启的持久幂等协议**。超出窗口或进程退出后，应先查询数据再决定是否重新创建。
- 窗口取消仅防止尚未执行的显示回调；已经显示的窗口或正在运行的确认对话框不会被强制销毁。

## 3. 数据兼容与故障边界

`leo-notes.json` 继续是原来的 `StickyNote[]`：Id、Text、Created、Updated、TaskId、Pinned 均保留；不转换个人文件，也不改清单存储。置顶排序和已转待办的独立收纳保留。

写入失败时原文件和内存快照不变，草稿留在编辑器。已删除 ID 的旧编辑请求明确失败，不再意外另建便签。退出时先处理便签的未保存文本，再关闭分发器；观察回调回到 UI 线程，窗口释放时解除订阅。

沿用“先建待办、再关联便签”的旧转换流程。关联保存失败后，宿主在本次运行中记住已经创建的待办 ID，关闭重开便签窗口后重试只补关联，不再次创建待办。此收据未持久化；**仍不保证两个文件在进程崩溃时具有跨文件事务性**。跨模块持久去重留给 Q4，不借本批重写清单。

错误分类包括 `invalid_request`、`storage_failed`、`host_closed`、`note_failed`。即使模块错误码映射本身出错，宿主也回退到 `action_failed`，避免请求悬空。查询结果只返回给调用者；诊断历史不保留便签正文。回放缓存只存在于内存，不导出成日志。

## 4. 与 Q2 的兼容

旧 `ILeoModule` / `LeoModule/1` 不变，本机应用继续使用 `coalesce-inflight`。新模块可实现 `IActionRequestAdapter`，宿主按接口适配结构化请求，无需为每个模块添加参数解析分支。默认输入上限仍为 16000 字符，便签显式声明最多 125000 字符的传输上限，以容纳 20000 字符中文经过 JSON 转义后的正文；存储正文限制仍是 20000。

`ActionPayload.PrivateData` 可标记只向本次调用返回的数据，历史记录去掉该部分。执行结果、计数和追踪继续复用 Q2 分发器，不增加第二套日志或网络服务。
