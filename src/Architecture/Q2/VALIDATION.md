# Q2 定向验证

日期：2026-10-19。开发基线为 Q1 提交 `72292c1`；本轮只测试注册/执行、应用入口、直接关联的取消路径与性能，不运行全量皮肤、足球、音乐或清单业务测试。

## 功能

锁定依赖构建通过，0 警告、0 错误。最终开发构建 **60/60** 项通过，布尔结果见 [checks.json](checks.json)。覆盖：

- 注册表复用、重复标识拒绝、旧63动作各有唯一归属；第二个本机应用只增加数据即注册，保留各自参数和图标。
- 旧 ID 与 canonical ID 合并；不同请求 ID/来源共用一个执行 ID；参数、工作目录、管理员选项不被入口覆盖。
- 正常、失败、显式重试、停用、移除、配置变化、确认修复、单个/全部订阅取消、独立期限、超时、退出和迟到返回。
- 结构化协议/参数校验、远未来期限、过期期限、空标识，以及启动接受证据与历史写入失败隔离。
- 实际快捷按钮、搜索选中、聊天和直接语音转写处理进入同一个应用动作；语音只注入识别后的文字，不打开麦克风、不调用模型。
- 关闭聊天取消其应用订阅；旧模块文字结果、扩展更新/移除、递归拒绝、旧请求合并/停用取消保持兼容。

启动器、启动失败、未返回的系统调用和历史失败均用本地假实现注入，没有启动用户应用或请求提权。合并和时间限制测试同时核对副作用计数，避免仅仅断言返回字符串。

## 性能调查

沿用 Q1 的方法和预定调查门槛，3个新进程样本。历史比较中首次显示耗时越限，其余所测 CPU、分配、私有内存、窗口/消息泵和取消耗时未越限。原始失败/调查批次保留 `.build/q2/initial-eager-registry`，没有放宽门槛或删除越限项。

内置注册表改为按需创建，避免纯桌宠启动时提前建立所有动作映射；分段诊断显示注册表构造约2ms，并不是数百毫秒差异的主要部分，因此没有继续改动未受影响的绘制或主题代码。

另用原有、未修改的 `--performance-test` 对安装中的旧 DLL 和新 DLL 交替采样各3次，显式使用相同运行时/依赖并校验关键图集一致。同场旧版与新版都明显慢于历史值，未复现新版相对旧版的首次显示回归。详细数值和限制见 [COMPARISON.md](COMPARISON.md) 与 [comparison.json](comparison.json)。不将控制实验当作已找到系统环境变化原因，也不宣称此次优化提升了真实软件启动速度。

短时采样不是全天稳定性或无泄漏证明；未启动真实应用测速度，未测冷启动、网络总请求率、真实用户媒体/比赛/语音负载。分发器计数不是全局网络埋点。
