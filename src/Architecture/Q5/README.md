# Q5：大脑受控接入

交付日期：2026-10-20。本批仅接入已迁移的配置应用、便签、比赛安排和保存组合；保留现有本地入口、中转站地址、协议、模型及加密 Key。没有制作发布包、更新发布材料或上传 GitHub。

## 1. 能力从模块声明进入模型

新增 `IBrainContributor`。模块声明自己的 `BrainAction`：稳定动作 ID、名称、输入种类、只读属性、参数说明、可引用的结果类型、校验回调及可选的本地预览。`BrainCatalog` 从实际注册表筛选启用且满足已知依赖的声明，不再向真实 Leo 聊天固定暴露全部旧动作。

本机配置应用的路径、工作目录失效时不提供给模型，调用前仍重新检查；应用配置以指纹绑定预览。模型只能按已保存的配置启动，不得传入路径、参数或管理员覆盖。完整路径、启动参数和管理员状态只显示在本地确认预览中，不放入模型能力清单。

便签仅提供查询、新增和窗口入口，不暴露内部关联/删除等动作；比赛提供真实赛程查询及引用桥接；组合提供已有名称，不向模型开放恢复确认、任意代码或自由组合配置修改。足球事实查询暂用原提供者适配，停用足球后同步移除。

这不是第三方代码沙箱；声明者仍是受信的宿主内模块。依赖检查只表示当时已知条件满足，不保证应用一定启动成功或网络一定可达。未迁移功能继续通过原明确指令、按钮和菜单使用。

## 2. 三条处理路径

| 请求 | 处理 |
| --- | --- |
| 明确打开软件、记下便签、切换代理、使用保存组合等本地口令 | 沿用本地路由和统一执行器；无需 Key 或模型 |
| 明确赛程、积分等事实查询 | 对应数据模块获取，缓存及来源规则不变；不能把模型常识称为实时查询 |
| 模糊理解、总结、临时规划 | 按需调用现有中转站；模型使用受限查询和计划工具 |

已迁移能力的模型工具为 `leo_catalog`、`leo_action` 和 `leo_plan`。前者返回可用动作及保存组合名称；第二个只允许查询；第三个只准备预览，不执行动作。现有独立旧接口适配保留给兼容调用，真实 PetForm 的聊天附带新 BrainSession。

## 3. 临时计划与确认

模型最多提出4步，每步只能引用当前可用动作及已校验的参数。步骤按序编号，结果引用只能来自此前步骤，且类型与模块声明一致；比赛的 Reference 由真实查询结果传给入清单动作，不接受模型编造开赛时间。

比赛 ID 必须来自本轮实际返回且可安排的赛程。多场候选不任意选择；明确球队及“下一场”可用来源数据消歧，其余情况要求用户补充场次。同名应用目标也不随机选择。保存组合必须先从实际清单取得名称，且只能作为单独计划，不能用多个组合绕过模型计划的步数约束。保存组合本身仍按 Q4 的最多12步及其期限执行。

计划展示完整待保存文字、应用固定配置和组合具体步骤。生成计划后停止模型工具循环，宿主明确显示“尚未执行”。没有模型可调用的确认工具；只有用户点击本地“确认执行”才进入 Q4 的 `ReliableWorkflow` 与同一 `ActionDispatcher`。

预览5分钟有效。目标停用、路径失效、应用参数或保存组合配置改变后，旧预览不能继续执行；新消息、清空对话、取消计划和关闭聊天会撤销旧计划。执行期间可停止，失败保留已完成步骤；未知效果先核验，无法核验时必须明确确认重试，不能默默从头执行。返回界面不会错误声称刚才已执行的计划“没有执行”。

临时计划只在内存存在，不会启动时自动恢复，也不会长期保存参数和私人正文。进程重启后的恢复范围仍以 Q4 已保存组合为准，不将临时计划宣称为跨重启事务。

## 4. 有界上下文和降级

- 能力声明最多64项，足球事实适配单独加入；不启动额外监控或常驻轮询。
- 历史最多6轮，每条历史用户/助手文字最多1000字符；模型的新消息最多12000字符。发送前检查对话文本及工具调用上下文最多32000字符。这些是字符限制，不是供应商计费 token 保证。
- 每轮最多3次模型请求、8次工具请求，模型阶段整体等待90秒；计划确认阶段另有120秒整体期限，单步沿用 Q4 的默认30秒。
- 查询数组最多8项、长字符串最多700字符，单个返回文本最多10000字符；结果过多要求缩小范围，不继续把大量数据塞给模型。
- 查询证据与待确认计划限于当前轮和有效期；新消息清除旧证据。没有新增持续采集屏幕、剪贴板或窗口内容。
- 私人便签查询要求本轮明确涉及便签，明确拒绝时阻止查询；这只是保守的有限措辞检查，不是完整自然语言授权解析器。写入仍始终要求计划确认。
- 接口拒绝工具请求时不自动追加请求；用户可点击“仅文字重试”，下一次请求不带工具。不支持工具的接口不能因此让模型直接执行文字中的动作。
- 保留已有日用量上限与账本，不改变 Base URL、协议和密钥保存方式。没有 Key、模型超时或预算耗尽时，本地口令、按钮和保存组合仍独立工作。

模型普通文字回复保留流式显示；动作是否完成以宿主预览和执行回执为准。模型仍可能生成错误文字，不把语言模型当作执行凭证。

## 5. 扩展已有模块的最小约定

模块在自己的实现中实现 `IBrainContributor`，而不是修改聊天的集中动作分支。只声明适合提供给模型的动作，内部恢复/管理接口可继续留在普通注册表中。

`Check` 负责输入的业务约束；实际动作实现必须再次验证，不能只信模型 schema。`BrainAvailable` 做无副作用的已知依赖检查，`BrainStamp` 标记影响执行范围的配置；有敏感路径和参数时，通过 `Preview` 只向本地用户显示，不写到 Label/Hint 或远端能力清单。

输出引用用 ResultProperty / ResultKind 与目标 InputKind 对齐。将返回数据视为资料，不能通过其中的文字增加动作权限。声明接口不等于已实现第三方模块包加载、独立更新或卸载；这些留给 Q6。
