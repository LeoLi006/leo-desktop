# W/B：现有组合与大脑数据衔接验收

日期：2026-10-21；基线c61113e。本批只核对“比赛查询→加入清单”和“便签→转为待办”，复用既有执行路径，不新增业务、模型权限或流程形式。

## 两条真实路径与权限

| 路径 | 当前执行与确认 | 去重与恢复 |
| --- | --- | --- |
| 大脑安排比赛 | FootballCapability返回真实赛程 → BrainSession记录本轮比赛编号 → 用户预览match_lookup/match_add → 确认前从现有缓存核对目标 → ReliableWorkflow执行 → MatchPlanningCapability经TodoClient提交 | 比赛以espn:EventId持久去重；失败步骤状态未知时不自动重放，显式重试仍使用同一比赛身份；完成计划不能再次确认 |
| 已保存组合的比赛链 | 同一ReliableWorkflow、注册分发器、MatchPlanningCapability和清单服务，Reference结构化传递 | 原日志/取消/未知状态核验规则保留；已保存组合按其原规则读取当前事实，不冒称所有组合都有大脑的本轮比赛预览 |
| 本地便签转待办 | NotesForm保存原文 → 原转换回调确认标题/日期 → TodoClient.Add携带原便签origin → NotesClient.Link关联任务 | 待办按便签身份去重；关联保存失败保留pendingLinks，重试复用已提交任务；原文保留，完成转换后按钮禁用 |
| 大脑读取便签及新建待办 | 明确请求才能note_query；公开todo_add只能创建经过预览的新事项 | 模型无note_link及指定便签origin的权限，因此不能把“读取便签后新建事项”宣称为完整的原便签关联转换。本批不为统一链路扩大这些权限 |

便签UI为既有分段提交流程，并非新增的原子跨Store事务或通用工作流步骤。部分成功时待办可能已经存在而关联尚未保存，不能显示为整体完成或取消已撤销；原pendingLinks与持久便签身份负责恢复。

## 已复现问题与修复

初次19项检查中1项失败：模型计划预览后比赛开赛时间变化，确认仍成功，并按新时间创建清单，与用户看到的预览不一致。

BrainSession.Confirm在原能力/配置检查之后、写入流程之前，对计划内显式选择的match_lookup/match_add身份，通过已有match_lookup重新读取缓存。核对编号、双方球队、开赛时间、未开赛/时间已定状态及取消/延期标记。目标变化或无法核验即停止，要求重新查询及预览；不会静默替换时间。

核验不联网、不新增动作/工具，也不重新执行写操作；每个不同比赛身份最多额外一次原缓存查询，来源标为brain-verify。其他计划不增加此读取。预取消仍不会进入写入流程。

边界：核验针对确认时的现有缓存，不代表已联网获得最新赛程，也不冻结整个执行期间的赛程。固定组合与模型计划仍使用同一执行器，但拥有各自既有确认上下文；本批未建设跨模块锁、通用补偿、并行或原子事务。
