# M05 第一批：代理与媒体能力迁移

日期：2026-10-20。批准范围为现有 Clash 和媒体控制，不扩张业务功能、不改按钮位置，不新增依赖，也不更换发布版本。

## 统一执行路径

`ProxyCapability` 接管 `proxy_status / proxy_on / proxy_off`；`MediaCapability` 接管 `media_open / media_status / media_file / media_toggle / media_play / media_pause / media_next / media_previous / media_stop`。旧动作字符串和配置继续兼容，新结构化请求也由同一模块适配。

注册表新增严格的内置能力替换入口：只能替换所属模块的完整既有动作集合，禁止跨模块抢占或剩余动作落回旧分支。移除本轮对应的 LeoActions 旧分支及已无调用者的代理/媒体 Hub 包装，保留音乐使用的原 Hub。

- Leo 脚下的代理状态与开关、菜单、搜索、聊天、语音、组合都进入分发器。
- 媒体窗口的会话刷新、打开 PotPlayer、打开文件和控制按钮共用分发器；窗口打开也经模块窗口服务切回 UI 线程。选择播放器仍是本地 UI 状态。
- 同一在途动作合并；每个客户端各有串行队列，相反代理目标及不同媒体操作按进入顺序执行，代理不会阻塞媒体队列。
- 共享队列跨配置代际保留。改变模块开关或程序路径会替换能力实例，取消失效代际；路径修复后同步刷新，避免模块一直停留在旧配置。正在路径修复的旧请求会结束，用户可从原入口重新发起，不自动重放可能生效的动作。
- 结构化代理参数必须为空对象；媒体控制仅接受 `session`，文件入口仅接受 `path`。旧文字参数同样做校验。

## 就绪、取消与结果证据

代理继续沿用原生静默启动、等待就绪和底层切换逻辑；迁移不改客户端 UI 自动化实现。执行后再读取状态，只有明确观察到目标值才给出 `state-observed`。读取不出、被其他代理接管或客户端关闭时，不把不确定状态当作关闭成功。

代理切换期限60秒，状态读取5秒，媒体45秒。组合步骤继承已迁移能力声明的期限；模型代理计划也使用60秒，避免旧30秒默认期限提前截断冷启动。整体聊天/计划已有预算仍生效，不承诺任何客户端一定在期限内完成。

长操作和排队可显示进度，约1.8秒后提供取消。取消及关闭结束等待，不杀掉已经由用户打开的客户端，不撤销已经提交的外部动作。提示绑定操作身份，结束时收起对应取消提示；没有直接调用原生操作的自动重试回调。

媒体发送后读取同一会话：播放/暂停/停止状态匹配、可确认的播放切换或曲目变化才作为观察证据；未知状态、会话消失或验证失败只报告 `accepted`。验证失败不会重发上一首/下一首等动作。显式会话失效时拒绝操作，不转而控制其他播放器。直接本地口令仍沿用已选播放器的原有选择规则。

PotPlayer 打开只确认系统启动请求已提交，不声称已播放；启动返回的进程句柄立即释放，不终止客户端。媒体窗口和工具条的异步回调检查关闭状态，工具条取消资源释放可重复调用。

## 大脑与组合

模块声明通过 Q5 注册表发现，不另写集中工具清单。代理缺少可用客户端路径或模块停用时不提供其模型动作。媒体查询和控制窗口可先发现；只有实际查询到会话后才提供控制能力，不因缺少 PotPlayer 就禁用 Windows 媒体会话。

模型媒体控制必须使用本轮查询返回的精确会话身份，多播放器没有明确目标先澄清。模型不能直接执行写操作，仍生成最多4步计划，预览确认后复用 Q4 执行器；配置变动使旧计划失效。播放器关闭后，执行前的新查询也会拒绝旧身份。

组合代理恢复核验通过注册表查询，不再直接绕过能力访问客户端。已经完成的代理步骤在媒体失败后恢复时不会重放；媒体效果无法核验仍沿用显式确认重试规则。查询与执行皆本机处理，无需模型 API。

媒体会话标题/曲目信息仅在查询结果和当前窗口使用，不留在分发器历史及模块运行摘要中；操作诊断使用简短回执。模型只收到本次工具查询实际返回的有界数据。

## 边界

M05 只迁移代理与媒体，M06 只删除这两类对应的过渡旁路。足球提供者、清单、音乐、剪贴板和语音后端仍待单独批次，不把整个阶段勾选完成。独立代码包、进程沙箱、模块市场也不属于本次交付。

验证见 [VALIDATION.md](VALIDATION.md)。本批只本地 Git 和一次必要更新，不打包、不更新 GitHub 发布材料、不上传、不用真实 Key 测试，也未实测真实客户端状态变化。
