# Q1：资源基线与后续比较方法

关联源码：BaselineProbe.cs、Measure-Q1.ps1。数值汇总：[MEASURED.md](MEASURED.md)、[measurements.json](measurements.json)。原始报告留在仓库忽略的 `.build/q1`，不读取/导出 app 的设置、剪贴板、对话或任务正文。

## 1. 三类测量不能混为一谈

| 模式 | 实际运行什么 | 主动关闭/避免什么 | 可回答的问题 |
| --- | --- | --- | --- |
| preview | 新进程、预览 PetForm，四种场景，每场预热1.2秒、采样8秒 | 索引、上下文记录、剪贴板、提醒/同步/全屏等真实后台计时器、全局快捷键；不启动外部客户端 | 固定预览负载的绘制、窗口和取消成本；不是实际常驻成本。 |
| companion | 干净构建目录、非预览 PetForm，六个可选模块都停用，真实宿主计时器开启 | 索引、剪贴板、上下文记录、自动更新、全局快捷键；没有个人任务或语音模型 | 纯桌宠形状的宿主成本，不能宣称“无后台活动”，提醒/专注等 core 仍属于当前宿主。 |
| common | 同上，六个可选模块启用；真实状态轮询与宿主后台计时器 | 与 companion 相同的隐私相关采集关闭；不播放/启动外部客户端，不切代理、不录音、不请求模型；空清单没有待同步比赛 | 启用模块但未主动使用时的空载成本，**不代表含真实索引、剪贴板、比赛数据的默认用户配置**。 |
| passive live | 对已运行的本仓库 Leo 读取约30秒进程计数 | 不切方案、不停止/重启进程、不读个人配置、不改外部状态 | 当前桌面活动下的一次实际观察；配置未控制，不能拿它与隔离模式计算“优化百分比”。 |

真实模式限定干净构建目录：发现设置、AI 配置、历史、清单、便签或模型目录时拒绝运行；不会在安装目录拿个人记录做测试。生成的空窗口位置/备份属于本地夹具，不用于发布。不以重装软件或更改用户使用方案来获取一张好看的表。

## 2. 场景与指标

每个隔离进程按 idle → docked → hidden → windows 顺序执行。静止吸附使用已有 PreparePerformanceScene；隐藏场景模拟“有意全屏隐藏”，临时停止全屏检测以免真实桌面将其立即展开，不打开新的全屏软件。windows 打开清单和通知窗口；另重复打开临时便签10次。固定顺序会包含首次加载吸附图集的驻留成本，因此不能把跨场景内存上升直接说成泄漏。

模块启停使用**真实 ActionDispatcher + 假的可取消 music_search 执行器**：运行10次启用、发起、停用、取消，核对都取消而非假成功。它测的是取消路径成本，不控制真实音乐、不测整个 UI 设置提交，不是所有模块资源都释放的证明。

记录：

- CPU：进程累计 CPU 毫秒；单核占用百分比 = CPU毫秒 /（墙钟秒 × 10）；整机归一百分比再除逻辑处理器数。二者不能混写。
- 分配与内存：进程范围托管累计分配差，私有字节、工作集；不强制 GC，不把托管分配当总内存，也不把工作集当私有内存。
- 资源：进程句柄，GDI/USER 句柄；帧数差。passive live 另记线程数，不跨进程猜测托管分配。
- 响应：消息泵间隔 p95/max 包含主动10ms sleep，是调度响应代理值，不是用户点击到显示的真实延迟。便签时间为 Show + DoEvents，不承诺首帧已被桌面合成器呈现。
- 启动：构造 PetForm 到第一次 Show 的耗时；不是 OS 冷启动、程序从磁盘启动或首次绘制耗时。新建进程也不能冒充清空系统文件缓存。
- 请求数：假执行器有确切执行计数；网络/本地客户端请求未全局埋点，标为**未测量**，不编写“0请求”的结论。以后要逐提供者接入计数并对敏感参数脱敏。

## 3. 可重复步骤

在仓库根目录构建后执行（不执行全量业务测试）：

```powershell
./scripts/Build.ps1 -Locked
./src/Measure-Q1.ps1 -Runs 3 -LiveSeconds 30
python ./src/Architecture/Q1/q1_audit.py
python ./src/Architecture/Q1/summarize.py
```

只补采当前运行计数用 `-LiveOnly`；只测一种夹具可用 `-Profiles companion` 等。进程不可见或不恰好一个时明确跳过 live，不能把缺失样本填成0；如系统限制读取进程，获准后在同一桌面权限下补采。单个隔离进程超时55秒终止并报错，报告先删旧文件，防止误读上轮成功结果。

原始 JSON 和生成的 ACTIONS.md/MEASURED.md 写入 `.build/q1`。审阅后只将不含个人字段的聚合数值/源码清册复制到本目录；脚本不会自动收集或提交 app。

## 4. 后续批次固定比较规则

Q1 是建基线，没有待比较的业务优化，因此不报告“提速了多少”。今后的同机比较在开工前采用：

1. 同一运行时、构建类型、DPI/皮肤/大小、场景顺序、采样时长、固定夹具和电源状态；前后各至少3个新进程样本。不将 app 自包含运行时与本机 dotnet 开发运行时直接比较。
2. CPU、分配、启动/响应的变差超过 **max(基线中位数的20%，基线样本极差)** 时标记调查；这是调查门槛，不是自动判合格。低于计时器分辨率的 CPU 不判“节省100%”。
3. GDI/USER/句柄比较同一场景和预热后重复周期，出现重复递增须延长检查并定位；不以单个瞬时读数或三十秒样本证明无泄漏。
4. 私有内存区分图集/模型首次加载与未释放资源；怀疑增长时才运行针对性的持续检查，不每批重复全量压力测试。
5. 先保留原始报告，再解释噪声。失败、跳过和无法控制的真实桌面干扰全部记录；不能测后调宽门槛或挑一轮最好数据。

## 5. 结果边界与后续缺口

本批基线覆盖固定宿主负载、启用/停用模块形状、静止吸附、合成全屏隐藏、窗口打开及假任务取消；附加一次未控制的真实进程观察。没有真实冷启动、长时间录音/模型、全应用索引、含个人比赛提醒、客户端播放或网络请求率对比。它们按对应模块迁移批次定向补测，不为完成 Q1 而触发用户的代理/媒体/隐私采集。

性能数据用于决定后续迁移是否回退，不作为所有电脑适用的 MB/CPU 保证。Q1 未新增常驻监控；除显式测试参数，正常启动路径不调用这些工具。
