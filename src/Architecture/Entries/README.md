# C05/R01：自定义应用入口试点

## 格式与范围

`leo-entry/1` 是宿主内部纯数据格式，由 `EntryContributions.Read` 从当前配置生成，不增加持久化格式或缓存。仅覆盖自定义本机应用。

`EntryContribution` 包含裸应用编号、模块/动作编号、名称、图标引用、启用状态、显示方式、搜索目标与简称、固定编辑器标识。快捷栏、菜单、搜索目录、入口设置和应用模块列表从它投影。不携带委托、控件、启动参数或可执行载荷。

## 归属及兼容

- 编号必须为原有 GUID；模块与动作同为 `local:<GUID>`。重复编号、跨归属动作或未知编辑器拒绝读取。
- 显示配置继续使用裸编号，缺省快捷栏；快捷栏顺序、菜单原始顺序、目标去重、收藏与原简称评分保留。
- 隐藏不改变启用状态。按钮与已打开菜单点击时重新确认存在且启用；最终执行仍经原注册表。
- 搜索匹配相同路径优先启用的自定义配置；仅有停用配置时仍保留关联，由执行器阻止绕过停用。
- 路径失效不阻止描述读取，保留路径修复。参数、工作目录与管理员选项只由原执行器处理。
- 编辑器从草稿生成同一格式，不启动客户端、读取 Key 或联网。运行描述含本机引用，不导出到公开清册。

## 验证边界

锁定构建零警告。入口专项57项、Q2原四入口启动60项通过，涵盖归属、重复编号、固定编辑器、更名、图标简称、隐藏、停用与移除，以及原显示排序启动行为。只做相关验证；内置入口、代码插件和新业务不在本批范围。


## 第二批：足球、音乐与媒体

三类内置入口复用 `leo-entry/1` 与 `EntryContribution`，固定归属分别为 football-data/football_open、music/music_open、media/media_open。`ReadBuiltins` 使用宿主固定白名单，不接受配置注入动作或编辑器。

- 统一快捷名称、菜单名称、设置名称、图标引用、显示方式、启用状态、固定设置编辑器及提示。原有不同场合的名称保留，不新增内置功能改名选项。
- 足球原按钮继续复用；音乐子菜单与媒体窗口保留。只将主入口及可见性接入描述，复杂窗口和子动作仍由原能力处理。
- 被动依赖状态仅表示手动路径：未配置 unknown、文件存在 ready、文件缺失 missing。不扫描软件、不调用修复、不启动客户端或请求网络。它不代表客户端实际就绪，也不作为打开窗口的阻断条件。
- 每次刷新按当前配置生成数据，无第二份状态缓存。停用时旧快捷按钮重新校验，菜单执行仍受原分发器与模块启用检查约束。
- 快捷入口设置由固定 editor 标识选择足球图标编辑或原应用配置编辑；不允许任意控件执行。

验证：锁定构建零警告；入口专项79项通过（新增22项），覆盖三类的归属、未知编辑器、默认显示、隐藏后可调用、缺失依赖和图标更新、停用与保留显示选择。原界面测试继续覆盖实际设置应用、菜单、快捷顺序与停用清理。Q2原四入口启动60项作为共享描述变更的兼容检查。无需真实 Key、客户端启动或收费接口。


## 第三批：终端、Clash 与 Edge

三类可选工具接入同一描述。脚下工具栏的图标、可见性、辅助名称，以及菜单和入口设置的显示模式/启用状态均读取当前描述。原工具位置与顺序不变，不增加主搜索窗口上方的按钮。

- 终端动作仍为 terminal_open，保留管理员启动；脚下按钮执行前重新检查启用状态。
- Clash 主描述为 clash/proxy_status，固定菜单子项为 proxy_on、proxy_off、proxy_status。原状态轮询、开关、连续点击保护和启动等待流程保留；隐藏入口不停止已启用的状态检查，停用停止计时器。
- Edge 能力动作为 web_search；菜单描述明确保留 launcher_open + web，脚下按钮仍展开原搜索框。菜单执行前额外核验 Edge 所属模块，避免通用窗口动作绕过停用。隐藏或停用会收起已展开输入框，搜索回车前再次检查启用状态。
- 菜单子项是固定纯数据，不接受自定义动作、任意编辑器或控件。校验包括固定子项与参数，旧配置不增加新字段。
- 依赖仅被动读取已指定路径；读取描述不启动软件、不切换代理、不触发路径修复。

验证：入口专项109项通过，新增30项涵盖新三类归属与停用、固定子项、真实工具栏图标刷新/移除、搜索收起及重新启用。锁定构建零警告。未执行真实代理切换或应用启动，不重复验证未修改业务。


## 第四批：入口与实际注册表一致性

### 宿主接入与归属

宿主完成能力注册后用 `EntryContributions.Bind(prefs, registry)` 绑定当前配置；编辑草稿未绑定，继续使用纯数据描述。绑定为弱关联，不增加持久化字段或全局单例配置。入口读取时查询注册表真实动作归属，不执行动作、不检查客户端就绪、不读取模型 Key。

主动作必须归属描述中的 ModuleId，菜单子动作也必须归属同一模块。唯一明确的宿主转接是 Edge 的 `launcher_open`、参数 `web`，要求实际动作归属 core；调用前仍核验 Edge 主动作归属及启用状态。它不是对任意转接动作的放行。

### 隔离与恢复

- 主动作或菜单动作缺失、归属不同、注册表查询异常：入口附带固定错误码，隐藏对应按钮和菜单，旧点击重新核验并拒绝执行；不改用户原开关或显示方式。
- 自定义应用重复编号：隔离该编号全部定义，不随意选择其中一个。畸形编号或契约失败只隔离该应用，其他应用仍能注册和发现。
- `Read` 保留严格验证语义，供校验及测试；界面使用 `ReadAvailable` 安全投影。移除、停用、重复项均在当前配置重新核验。
- 已配置路径即使被隔离也不会退化为普通索引启动，防止同路径应用绕过自定义参数或停用检查。
- 配置修复或重新绑定有效注册表后，下次刷新恢复入口；不持久化故障或复制能力执行策略。

### 开发产物与验证

运行 `--entry-inventory <输出目录>` 使用固定隔离预览宿主生成 [清册](GENERATED.md) 与 [JSON](inventory.json)。导出白名单协议字段；本机应用 ID 替换为示例编号，不导出名称、图标、路径、简称、开关或业务正文。[编译样例](MinimalEntry.cs) 展示绑定与读取，不自动注册代码。

专项25项覆盖真实宿主归属、缺失/错误动作、Edge 转接、查询异常、重复及畸形应用隔离、旧按钮拒绝、修复恢复、实际快捷栏与清册脱敏。直接相关入口109项、Q2应用60项、模块契约55项通过。Q2重复编号断言随本批语义改为“隔离重复项且不影响其他模块”，原重复动作注册拒绝机制保留。不调用真实接口、不启动外部程序、不切换代理。
