# 电脑状态与邮箱模块方案

状态：原始方案及修订记录；首批已按下述收缩方向批准实施，见[交付说明](../DesktopTools/README.md)。日期：2026-10-21；依据当前模块化底座及本次官方资料核对。用户范围：火绒个人版、QQ邮箱、Gmail、校园邮箱。本轮只写方案并本地提交，不接真实账户、不扫描本机状态、不安装依赖、不改程序、不上传GitHub。

## 0. 用户修订与当前范围

用户后续明确：方便优先；火绒有可靠问题时提醒并打开即可，无有效接口不强行集成；邮箱复用现成应用，不自建收信与凭据；资源监测可自行开发。原文后续的QQ/校园IMAP、Gmail OAuth、邮件头同步等仅保留为历史候选，不是本轮实施清单。

首批：可选只读电脑状态、任务管理器/火绒打开、默认关闭的持续资源提醒；邮箱客户端直接启动与设置，账户/邮件/通知留给原客户端。两模块默认关闭，进入设置按需开启；不访问邮箱API、不上传GitHub。

## 1. 定位与建议顺序

两个方向都有价值，分别补齐“电脑正在发生什么”和“有哪些信息值得我处理”。建议分成两个独立可插拔模块，共用已有入口、主题、窗口、调度、反馈和数据边界，不把Leo做成另一个完整任务管理器或邮件客户端。

| 模块 | 定位 | 第一阶段成功标志 |
| --- | --- | --- |
| 电脑状态 | 轻量状态仪表盘；查看资源异常并跳转对应工具处理 | 不开任务管理器即可看CPU/内存及高占用进程；关闭/停用后没有无主高频采样 |
| 邮箱 | 多账户邮件速览；看到重要未读并快速回原邮箱 | QQ/一个明确支持的校园账户可查看头部信息与未读，离线/撤销授权不拖垮Leo；Gmail单独完成官方授权验证 |
| 火绒个人版适配 | 电脑状态中的可选软件入口/有限状态卡 | 能配置并打开火绒；只展示可验证的安装/进程状态，不假称已读取防护状态或病毒结论 |

建议实施顺序：**系统状态最小版 → QQ/校园邮箱只读试点 → Gmail授权接入 → 按需求增加显式动作**。可以调整顺序，但每批单独审批，不一次同时重写两个模块和全部宿主服务。发布/安装包仍另行安排。

## 2. 已核实与待验证

### 2.1 系统与火绒

Windows提供性能计数器与系统内存接口，可作为监测数据源。无需依赖任务管理器窗口，也不应通过读取其界面文本获取指标。[Windows性能计数器说明](https://learn.microsoft.com/en-us/windows/win32/perfctrs/about-performance-counters)、[GlobalMemoryStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex)。

火绒官方企业版帮助明确说明存在中心API；**这不能推出个人版也有同样接口**。本次没有确认个人版适用的公开稳定API或受支持日志格式，所以不将个人版实时告警、防护开关、扫描进度等列入确定交付项。[火绒企业版官方帮助](https://www.huorong.cn/service/support/fqa/common-problem-1/central-management/center-setting)。这是资料不足的结论，不是断言个人版永远无法集成。

Windows安全中心可提供安全类别的综合健康状态，但不是火绒个人版的逐项防护/查杀结果。若采用，必须独立标为“Windows安全中心报告”，服务不可用时显示未知。[WscGetSecurityProviderHealth](https://learn.microsoft.com/en-us/windows/win32/api/wscapi/nf-wscapi-wscgetsecurityproviderhealth)。

### 2.2 QQ、Gmail与校园邮箱

- QQ：候选路线为用户主动开启的IMAP与客户端授权凭据；实施前按QQ当前官方设置页面核对。本次工具无法读取其帮助页全文，不固定菜单位置、授权码长度或服务器配置为已验证事实，也不以用户主密码登录抓网页。
- Gmail：优先官方API和桌面OAuth/PKCE。gmail.metadata允许读取标签/邮件头而不含正文，但并非“无需授权审核的低成本权限”；其所处权限表涉及受限范围，面向公众分发须核对Google验证要求。[Gmail权限范围](https://developers.google.com/workspace/gmail/api/auth/scopes)、[桌面OAuth](https://developers.google.com/identity/protocols/oauth2/native-app)。
- 校园邮箱：尚未提供学校/服务商，不能假设都支持IMAP。可能为自建邮箱、腾讯/网易企业邮箱、Microsoft 365或仅SSO网页登录；先确认协议，再选择适配。属于Microsoft 365时，可评估委托Mail.ReadBasic读取基础属性，不含正文/正文预览/附件，仍受学校租户策略约束。[Microsoft权限说明](https://learn.microsoft.com/en-us/graph/permissions-reference#mailreadbasic)。
- IMAP协议支持邮件读取与修改。因此“Leo只读”首先是客户端行为约束，并不保证授权码只具服务器端只读权限。拟采用只读文件夹访问和不会标记已读的读取方式。[IMAP标准](https://www.rfc-editor.org/rfc/rfc9051)。

上述技术路线仍需实施前用测试账户/隔离数据验证；不是已接入的功能承诺。

## 3. 电脑状态：产品设计

### 3.1 日常入口与窗口

可在原快捷栏显示一个“电脑状态”图标，或选仅菜单/仅搜索。点击打开紧凑面板，顶部显示CPU、内存、磁盘剩余、上/下行速率与更新时间；下方列少量高占用进程，支持CPU/内存排序。沿用当前皮肤与窗口服务，不往桌面常驻铺多块浮窗。

每个指标同时具有数值、单位、采样时间和可用状态。缺失显示“不可读取/权限受限/正在采样”，不显示成0。网络速率不是带宽测试，磁盘剩余不是磁盘繁忙度。

底部提供“打开任务管理器”和可选“打开火绒”。系统指标直接采集，任务管理器负责深入操作。常用入口拟支持搜索“电脑状态”“内存”“占用”；这些是本地指令，不需要模型。

### 3.2 第一版范围

- CPU总占用、物理内存已用/总量、选定本地盘剩余容量、网卡累计字节换算出的上/下行速率。
- 高占用进程的名称、PID、启动时间标识及CPU/内存；首版只读，受保护进程字段可缺失。
- 显示采样窗口与“非瞬时精确值”说明，CPU采用两次采样差值并明确多核归一口径，不保证逐帧等于任务管理器。
- 磁盘剩余低频采集，避免每秒枚举移动盘/网络盘阻塞；进程列表限量、按需采集。
- 默认不常驻提醒。用户可选择持续高占用/空间不足提醒，连续多次采样达阈值后触发，带恢复阈值与冷却，防止频繁骚扰。

GPU占用/温度、CPU温度、每进程网络流量、开机项优化、驱动级采集、远程管理和自动结束进程均不纳入第一版。没有这些数据源时不安装驱动补齐，也不借“监测”默认请求管理员权限。

### 3.3 火绒个人版能力分层

| 能力 | 方案 |
| --- | --- |
| 路径配置/打开客户端 | 复用现有本机应用/客户端启动路径，用户明确点击才启动 |
| 可识别的运行进程 | 可选被动检测，说明检测对象与时间；名称匹配不能证明防护正常 |
| Windows安全中心综合状态 | 可选只读来源，独立标注，不冒充火绒专属数据 |
| 火绒个人版防护状态/查杀结果/日志 | 暂缓；先取得官方支持或验证稳定且允许读取的来源 |
| 修改防护/白名单、隔离恢复、静默查杀 | 首版不做；不逆向私有接口、不注入/操纵安全进程，不以GUI自动点击实现 |

若最终只有打开客户端，仍如实称“火绒快捷入口”，不包装成已经实现安全监控。电脑状态模块在未装火绒时照常可用。

## 4. 邮箱：产品设计

### 4.1 定位与界面

在原快捷栏/菜单/搜索新增可选“邮箱”入口；一个紧凑窗口，支持“全部账户/QQ/Gmail/校园”切换，展示发件人、主题、时间、未读标记和同步状态。默认只展示必要邮件头，不自动下载正文与附件。

点击邮件优先在用户配置的浏览器或默认浏览器打开服务商页面。存在经过验证的精确邮件深链时打开该封；无法定位时退到该账户收件箱并提示，不伪造链接。IMAP UID不能通用转换成网页版链接。

第一轮同步只建立基线，不将已有几百封未读逐条通知。新增未读默认只增加角标；用户选定账户/规则后才提醒，重要程度由明确规则决定，不先用模型判断。主题可在锁屏/通知中隐藏，完整信息在Leo窗口查看。

### 4.2 三类账户的路线

| 账户 | 优先实现 | 必须处理 |
| --- | --- | --- |
| QQ | IMAP+TLS、客户端授权凭据，优先只读文件夹访问 | 官方设置变化、授权撤销、连接数限制、UID/UIDVALIDITY、断网重连；不启用SMTP |
| 校园 | 确认学校/服务商后复用IMAP适配，或采用该服务商官方接口 | 租户限制/SSO/关闭第三方客户端；仅网页登录则保留网页入口，不绕过身份验证 |
| Gmail | 官方Gmail API、桌面OAuth+PKCE，第一版邮件头/标签所需范围 | OAuth应用注册、测试用户与公开验证、刷新令牌撤销、配额/网络不可达、范围能否满足实际查询 |

候选复用MailKit处理IMAP/TLS/取消及MimeKit解析邮件头，Gmail走官方HTTP API或官方SDK。MailKit项目提供IMAP/POP3/SMTP及MIT许可证；采用前还需固定版本、审核依赖与兼容，不能因为库支持SMTP就自动开放发送。[MailKit项目](https://github.com/jstedfast/MailKit)。本轮不引入依赖或复制代码。

### 4.3 第一版不含的能力

发送/回复、删除/归档、自动标记已读、附件下载、HTML正文渲染、规则转发和后台模型总结暂不纳入。这样既符合“便捷看邮件”的定位，也避免首版同时承担完整邮件客户端和高影响写操作。

后续若需要正文，先明确读取授权和界面预览范围；HTML要阻止脚本与远程跟踪资源。若需要“邮件转待办”，用户选中并确认标题/日期后只复制必要信息及来源引用，不自动把整封邮件存进清单。

## 5. 共用模块设计（拟议，不是已发布接口）

拟使用独立模块system-monitor与mail，火绒作为可选huorong适配器；各自独立启停、显示入口与后台开关。邮箱内部使用账户级Provider，不为QQ/Gmail/每个校园账户各写一套窗口。

拟议动作示例：

| 动作草案 | 参数/结果 | 权限 |
| --- | --- | --- |
| system_open / system_snapshot | 打开窗口 / 有时间戳与字段状态的系统快照 | 本地只读 |
| system_processes | 有限数量与排序枚举 → 进程快照 | 本地只读；不默认返回命令行/完整路径 |
| system_taskmanager | 无参数 → Windows接收打开请求的证据 | 用户触发外部动作 |
| security_open | 受控的已配置火绒目标 | 用户触发，不接受任意路径 |
| mail_open / mail_headers | 打开窗口 / 指定已配置账户的有限邮件头 | 私有只读，首版只对本地UI开放 |
| mail_refresh | 指定账户或全部已配置账户 | 合并在途刷新、限频、可取消 |
| mail_open_original | 已查询账户与邮件身份 → 服务商定位结果 | 用户触发；目标URL由Provider校验 |

动作名在实施时经现有契约校验再确定，不写进当前公开LeoActions清单。本轮没有新增HTTP接口、任意系统命令或模型工具。

拟议快照包含：采集/同步时间、来源、代次、字段可用性及失败/过期标记。进程身份使用PID+启动时间，防止PID复用；邮件身份采用账户+文件夹+UIDVALIDITY+UID（IMAP）或账户+服务商消息ID，不能只用列表下标或Message-ID当唯一依据。

窗口仍由宿主固定端口承载。若这两个窗口需要新增端口，应一次说明组装点；不顺便重构全部窗口。配置、凭据、业务缓存分开：模块拿限定服务和不含密钥的账户描述，凭据服务只供授权连接使用，不提供给任意模块或模型。

## 6. 采样、同步与鲁棒性

以下频率是设计起点，不是性能验收成绩，实施时按可见收益调整。

| 场景 | 拟议策略 |
| --- | --- |
| 状态窗口可见 | CPU/内存/网络约1～2秒，进程约3～5秒，磁盘容量约30秒；共用采集快照 |
| 状态窗口关闭 | 停止窗口高频采集；只有用户明确启用后台提醒时保留低频汇总，无进程轮询 |
| 邮箱启用后台同步 | 先采用分钟级可配置增量轮询，账户串行/限并发；支持的推送/IMAP IDLE另评估，不能承诺所有提供商实时推送 |
| 邮箱窗口打开 | 先展示有时间戳的缓存，再按限频规则刷新；重复打开不再新建同步器 |
| 断网/限流/认证失败 | 保留旧快照并标过期；退避与抖动，尊重服务商重试提示；认证失效停止重试并在设置提示重新授权 |
| 关闭模块/退出 | 取消在途任务、释放进程句柄/计数器/连接/订阅，旧代次不得写回或恢复窗口 |
| 休眠恢复/网络切换 | 重建采样基线；不出现负速率/超大CPU，不一次补发全部历史提醒 |

单项指标读不到不影响其他指标；单个邮箱失败不影响其他账户；火绒缺失不影响系统监测。错误集中显示在原状态/诊断中，仅保留类型和数量，不对每次重试弹窗。所有者与活动计数接入现有机制，不新增无归属常驻线程。

原始历史曲线默认仅保留小型内存环形缓冲，关闭后不建长期行为档案。邮箱缓存拟默认仅有限邮件头，按账户独立清理；不缓存正文。安全凭据和邮件头都属私有数据，不能进入可分享诊断或方案导出。

## 7. 凭据、权限与大脑边界

- 系统模块先以普通用户运行；权限不足的字段明确缺失，不将整个Leo提升为管理员。未来若增加结束进程，应另批设计真实身份核验、明确确认和窄权限辅助进程，首版没有这项动作。
- QQ/校园授权码与OAuth刷新令牌在本机凭据存储中保护，候选Windows Credential Manager或当前用户DPAPI。模块配置只存引用，不在JSON里保存明文；加密不等于能自动跨电脑迁移。
- Gmail使用系统浏览器授权，校验state/PKCE/回调及超时取消；桌面客户端不内嵌作为安全边界的服务器秘密。OAuth应用面向公众的注册/验证工作必须列入交付成本，不能让下载者以为填模型Key即可收邮件。
- 校园邮箱必须遵从服务商允许的协议/授权；不抓取浏览器Cookie、保存校园门户密码或自动绕过SSO。具体学校可在实施前私下提供服务类型，不需要在聊天中提交密码。
- 邮件和系统采样均不需要大模型API。首版不自动把邮件头/正文、进程清单交给模型；正文“作为不可信输入”也不能成为执行指令。
- 后续如用户主动要求总结，先预览具体选中内容与外发范围，再按当前模型配置/预算调用；服务商邮箱API/OAuth与模型API是两套授权，不混用Key。
- 移除账户停止同步并明确本机缓存/凭据的删除选择，不删除服务器邮件；分享模块包/使用方案不包含账户、服务器私有配置、令牌或邮件。

## 8. 组合价值与后续阶段

明确命令“看看电脑状态”“打开任务管理器”“打开火绒”“看看校园邮箱”可以本地路由，无需模型。之后可以在原组合中增加“开始学习：打开校园邮箱和清单”“电脑卡顿：展示高占用快照”，每一步仍走同一执行器。

后续候选而非首版承诺：用户选中邮件转待办、按明确信任发件人提醒、用户确认的进程结束、选中快照解释、符合官方接口条件的火绒信息读取。不能因为“控制大脑”目标就默认授予读取全部邮件或自动处置进程的权限。

## 9. 分批实施与验收门槛

| 批次草案 | 范围 | 验收/停止条件 |
| --- | --- | --- |
| P1 系统只读试点 | 聚合CPU/内存/网速/磁盘容量、有限进程、原主题窗口和入口；任务管理器及火绒打开 | 模拟权限失败/进程退出/计数重置不崩溃；关窗降频、停用归零、旧回调丢弃；不解析火绒私有数据 |
| P2 QQ与校园路线确认及只读试点 | QQ IMAP与一个已确认支持的校园测试账户，邮件头/未读/缓存/手动与受控后台同步 | 先假服务器/夹具；真实测试需单独授权。无Seen写入、无SMTP、无正文/附件下载；UID重置、断网、撤销、账户隔离正确；首次同步不轰炸通知 |
| P3 Gmail官方授权试点 | 桌面OAuth、最小可行邮件头查询与现有统一邮箱窗口 | 授权取消/撤销、测试用户与公开验证路径明确；不先假定可广泛发布。无法合规/可靠授权时保留网页入口，不退回抓Cookie方案 |

每批先给出范围，获批准后再实施。采用定向检查和必要资源短测，只有运行变化才统一更新一次；不为了本方案重跑全部既有功能。不承诺完成日期或未测量的CPU/内存上限。
