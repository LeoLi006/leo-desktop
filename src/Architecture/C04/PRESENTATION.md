# C04 第三批：窗口与反馈服务边界

## 固定窗口请求

`leo-host-presentation/1` 是宿主内部格式。ModuleWindowTarget 当前为 Applications、Football、Music、Media、Todos、Notes、QuickNote、Chat、Clipboard（清单便签见[第四批](PLANNER-PRESENTATION.md)，聊天剪贴板见[第五批](CONVERSATION-CLIPBOARD.md)）；IModuleWindowPort 只暴露带取消的 ShowAsync，不暴露控件或任意显示回调。模块原 show 委托保留兼容，正式宿主绑定固定端口。

| 目标 | 接入路径 | 宿主保留的原显示方式 |
| --- | --- | --- |
| Applications | launcher_open、应用名称有歧义时的搜索窗口 | ShowLauncher；原位置、焦点与输入预览。 |
| Football | football_open | Launcher.OpenFootballFromAssistant；原足球窗与位置记忆。 |
| Music | music_open | Launcher.OpenMusicCore；原点歌窗口。 |
| Media | media_open | ShowMediaCore；原媒体窗口。 |

应用搜索请求可带有限长度文字和 Web 模式；第四批为便签草稿及清单视图增加明确的数据字段，其他目标拒绝不适用参数。不存在任意窗口编号、控件实例或执行回调的请求字段。

## 取消、关闭与停用

每个目标保存独立代次。窗口隐藏/关闭、模块启停改变时使旧代次失效；宿主调度到UI线程后再次校验代次、启用状态及取消。快速停用后重开不能复活旧请求。宿主销毁时，排队任务按原调度器规则结束。

- 应用搜索隐藏时失效；足球及媒体窗口关闭时失效。
- 音乐原“关闭”实际隐藏窗口，因此同时接入隐藏事件，保持原复用窗口行为。
- 各类目标独立，单个显示回调异常只使该请求失败，不污染其他目标或后续请求。
- 只丢弃未执行的旧请求，不回滚已经显示的窗口或已提交的客户端动作。
- 原 ModuleWindowService 两参数方法保留；增加带有效性检查的重载，不要求其他模块同步迁移。

## 结构化反馈

ModulePresentationFeedback 接收 ActionResult，并验证模块归属。普通成功仅在请求明确确认时输出，失败沿用错误提示策略，取消不输出成功。应用/足球的已迁移菜单及音乐菜单读取结构化结果；本批不增加普通操作弹窗。

音乐与媒体 NativeCapabilityQueue 使用宿主所属的进度反馈租约。租约在UI投递处检查取消、窗口代次和自身是否结束；旧进度不能在结束后再次显示。取消按钮继续由原 ClientOperation 提供，属于宿主内部回调，不进入固定窗口请求协议。

租约结束仅清理匹配 OperationId 的忙碌提示，避免误关新操作的反馈。界面或反馈接收器异常不改变客户端动作结果。Clash及未迁移入口仍保留原反馈适配器，本批不扩展其业务。

## 样例与验证

[编译样例](MinimalPresentation.cs) 展示模块仅持固定窗口端口和结构化反馈。实际窗口的位置、焦点、主题、Esc及返回逻辑仍由原宿主方法负责。

锁定构建零警告。专项45项及直接相关321项通过：客户端46项、音乐/剪贴板54项、足球52项、应用四入口60项、入口显示109项。包括真实预览宿主四窗口打开与Esc关闭、关闭后的旧反馈丢弃；排队取消、关闭、快速启停、错误目标/参数、跨归属反馈、单窗口失败、宿主销毁、记录接收器失败和进度租约结束。

新增真实预览测试最初发现音乐隐藏未使反馈失效，已修复并通过专项及音乐定向复测。没有网络、真实Key、外部客户端启动或代理切换，不重跑无关全量测试。
