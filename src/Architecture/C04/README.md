# C04：自定义应用宿主服务最小试点

## 目标与边界

`leo-host-application/1` 是宿主内部服务契约，不是模块包协议或进程间协议。仅迁移自定义本机应用；不改界面、动作编号、个人配置格式或业务权限，不代表已完成 C04 全部宿主服务。

`IApplicationHostServices` 只提供：

| 服务 | 数据及限制 |
| --- | --- |
| ReadConfiguration | 当前这一应用的不可变 LocalApplication；移除返回 null，不接受任意模块编号。 |
| ReadDependencies | 对这一应用配置被动查询程序文件、工作目录；不扫描、不修复路径、不启动软件。 |
| RecordFault | 阶段枚举与异常类型；宿主自行附加模块编号，不接收异常消息、堆栈或业务正文。 |

宿主在注册时构造限定应用编号的服务。模块不接收 Preferences，不直接查询文件依赖，也不持有注册表或整份配置。旧构造参数仍经适配服务兼容。该边界是宿主架构约定，不是对同进程代码的安全沙箱。

## 执行与配置一致性

- 执行仍用 ApplicationCapabilityHost：核验当前配置、准备/修复路径、再次核验、原启动参数和工作目录、管理员选项、历史记录。
- 服务在调用时读取当前配置；更名/参数变化被原配置代次比较发现，停用/移除阻止继续执行。准备完成的已确认修复仍可更新模块配置代次。
- 默认服务检查编号归属，模块再次校验配置归属，避免误接入服务返回其他应用配置。
- 模型依赖可用判断改用同一服务；继续保持被动文件检查，不扩大模型权限或启动范围。
- 保留统一执行器的取消、合并请求、超时与结构化结果；本批不改变对应策略。

## 故障记录

ApplicationHostFaults 为注册表所属、有锁保护的128条内存队列；快照为独立数组。每条仅含 Module、Phase、ErrorType；不写入个人文件，不弹普通操作通知，不增加后台线程。

配置、依赖、执行异常按阶段记录后继续保留原异常类型和原失败语义。取消及配置变化不作为故障记录；记录服务自身失败不会覆盖原异常或触发再次启动。该新增记录不修改既有统一执行器的错误返回格式。

## 接入与验证

[编译样例](MinimalApplicationServices.cs) 展示限定服务的创建与注入。样例不会自动注册或启动应用；下一模块迁移前仍需单独审批。

专项30项、直接相关Q2应用60项、模块契约55项、入口一致性25项通过，合计170项。使用模拟配置服务、依赖结果、故障记录器及假启动器，覆盖配置更改、停用移除、路径修复兼容、取消、跨模块配置拒绝、读服务异常、记录器异常、故障脱敏和容量上限。锁定构建零警告。真实进程启动、真实Key和网络调用均为零。

Q2首轮有一次原50ms订阅期限断言未通过；未调整业务期限或放宽断言，独立复测通过，首轮与复测报告保留在忽略的构建目录。未扩展到无关功能测试。
