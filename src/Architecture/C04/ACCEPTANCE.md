## 验收矩阵

| 方向 | 已交付及源码依据 | 阶段结论与限制 |
| --- | --- | --- |
| 配置 | [应用服务](../../ApplicationHostServices.cs)只读一个应用配置；[客户端服务](../../ClientHostServices.cs)只给启用/代次等限定值 | 应用与Clash/音乐/媒体子集已接入。不是全部模块通用配置服务，部分宿主仍持有整份Preferences |
| 数据 | [ModuleJsonData](../../ModuleHostServices.cs)支持先原子保存再发布；便签与流程使用它，清单保留原Store及提交语义 | 已有可靠保存原语和统一业务路径；尚不能声称每个模块都经同一格式声明并获取限定数据服务；直接注入专用Store并不自动构成缺陷 |
| 依赖 | 服务被动读本机依赖，契约描述与注册校验覆盖11类91动作的既有清册 | 子集可复用；运行前仍需业务核验，不保证网络或外部应用一定可用；没有完整外部兼容范围协商 |
| 日志/反馈 | ApplicationHostFaults有界内存记录，ModulePresentationFeedback/进度租约连接原安静反馈 | 已接入路径可隔离失败，摘要不带正文；不是通用持久日志/全局请求账本，其他原适配保留 |
| 窗口 | [ModulePresentationService](../../ModulePresentation.cs)绑定九目标端口，UI投递带取消和代次，宿主退出先停服务 | 九目标子集验收；新复杂窗口仍需宿主固定目标与创建逻辑，不能自动加载任意控件 |
| 主题 | [ModuleThemeBinding](../../ModuleThemeService.cs)在九类窗口订阅值快照，隐藏退订、关闭释放 | 已迁移窗口验收；仍桥接UiTheme全局映射，不是进程外主题服务，全部设置弹窗及字体存量资源未重做 |
| 周期调度 | [IPeriodicTask](../../IPeriodicTask.cs)由原实现直接实现，窗口适配继承；九类周期任务有明确所有者 | 已迁移周期任务验收；UI线程契约，非周期STA、动画和输入防抖不在此范围；没有通用资源容器 |
| 受控调用 | [CapabilityRegistry](../../CapabilityRegistry.cs)、[ActionDispatcher](../../ActionDispatcher.cs)及Q5预览路径供既有能力调用 | 复用既有校验/取消/证据；不是所有模块可持有完整执行器，服务授权、流程及外部权限不能据此扩大 |
| 诊断 | HostServiceDiagnostics及ModuleActivities输出类型与数量，主题计数明确标为进程级 | 被动数量摘要已验收；不覆盖所有任务、全局耗时或真实长期负载 |

“阶段验收”仅指已接入范围有实现、明确所有者及相应模拟证据。不是全部目标已通过，也不把原生进程故障纳入普通异常捕获保证。

## 接入样例能复用什么

| 已有样例 | 可复用部分 | 不能据此推定 |
| --- | --- | --- |
| [MinimalApplicationServices](MinimalApplicationServices.cs) | 限定配置、依赖、故障记录注入已有应用执行器；不传整份配置 | 任意新业务都适用应用专用接口，或能直接独立安装代码 |
| [MinimalClientServices](MinimalClientServices.cs) | 客户端启用、代次及被动状态边界 | ClientHostServices中的已知客户端范围已变成通用插件工厂 |
| [MinimalPresentation](MinimalPresentation.cs) | 模块拿固定端口及结构化反馈，宿主拥有窗口 | 模块可任意创建宿主窗口目标或持有控件 |
| [MinimalContractModule](../Contracts/MinimalModule.cs) | 无UI、无外部依赖的模块可声明/校验/执行结构化动作 | 已把配置、存储、主题、调度等服务组合成一个新增模块全链路样例 |
| [MinimalEntry](../Entries/MinimalEntry.cs) | 已注册能力与既有入口描述做归属校验 | 任意新模块都能在不修改集中入口生成器的情况下声明全部UI |
| [主题接入](THEMES.md)、[窗口调度](WINDOW-SCHEDULING.md)、[宿主调度](HOST-SCHEDULING.md) | 实际编译窗口和宿主是现有接入样例；只用所需服务，不复制执行算法 | 已发布可供任意外部代码使用的稳定服务包或进程间协议 |

普通“数据型本机应用”新增第二项已有配置驱动路径；普通“无UI状态模块”也有注册样例。但更复杂的新业务仍需要宿主组装服务、注册模块或固定窗口，需在C04-G2验证实际缺口后再补通用接入点。现有证据不支持引入全能ServiceLocator或一整套新插件框架。
