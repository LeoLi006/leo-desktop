# C04-G1/G2：便签数据边界与普通模块联合样例

日期：2026-10-21。对应[阶段验收](ACCEPTANCE.md)的受限数据与无UI接入验证，非完整C04完成声明。

## 现有便签边界

NotesForm/QuickNoteForm通过NotesClient进入已注册便签能力。查询返回独立列表，StickyNote是不可变记录；保存沿NoteStore → ModuleJsonData原子提交，成功后才发布Changed。界面草稿不是自动的数据提交，速记失败保留输入，列表关闭沿原保存/确认行为，不更改这些用户规则。

NotesClient不持有全局Preferences；NoteStore只绑定宿主创建时给定的单个文件。专用Store本身不是必须替换的缺陷。本轮复用其查询、文件格式、请求去重、保存失败保护和客户端语义，不引入另一层生产存储接口。便签查询仍可能包含私有正文，不默认扩大模型权限。

## 编译样例与宿主组装点

[ScopedNotesExample.cs](ScopedNotesExample.cs)提供三个部件：

| 部件 | 责任与限制 |
| --- | --- |
| IExampleNotesServices / ExampleNotesConfiguration | 只提供本例启用/长度配置、依赖摘要、查询和保存。无路径、全局配置、任意动作、窗口或模型权限 |
| ScopedNotesExampleServices | 宿主绑定一个NoteStore和限定配置读取器；复用原NotesCapability的数据操作、重放缓存及序列化规则，ActivityOwner负责取消/释放 |
| ScopedNotesExampleModule | 实现现有模块契约、参数适配和结构化执行接口；两个示例动作接受唯一text字符串字段；检查依赖并复用统一注册/执行，不自建执行器 |

最小组装顺序：宿主选择隔离文件并创建NoteStore → 创建限定服务 → 将服务注入模块 → Registry.Register(module) → ExecuteStructuredAsync请求 → 退出时释放服务并关闭宿主分发器。

只有显式 `--scoped-services-test` 测试路径执行这组装；生产PetForm/模型目录不注册样例。新增这样的无UI模块不必修改ActionDispatcher或CapabilityRegistry中的业务分支，但宿主仍必须显式组装并注册，不能假称已具备自动加载任意模块的工厂。

不提供界面，因此无需虚构窗口/主题/调度依赖。需要这些服务的新模块仍按固定窗口端口和原主题/周期任务契约接入，超出既有固定目标时另行评估宿主扩展点。此样例服务是内部、可信、显式注入的格式，不是可安装代码模块协议或权限沙箱。

## 请求、失败及关闭

样例纯参数解析不读配置服务。实际配置与依赖读取可能失败，必须处于分发器执行边界内，转成结构化失败，避免异常在适配阶段逃逸。业务及服务异常不影响另一个已注册模块。

相同请求标识和相同保存文字复用原便签重放结果；不同文字复用标识被拒绝。重放只保护原有进程内有界缓存范围，不承诺跨进程永久幂等。原写入失败不发布内存快照/Changed，显式重试可提交。

取消发生在服务调用前时不保存；服务关闭后新调用及迟到调用拒绝。已经提交的保存不能以“关闭”或“取消”等同回滚。查询返回前校验当前服务租约，保存保留原已提交结果；样例未新增自动重试或补偿语义。

宿主拥有服务和Store绑定，模块不拥有整个宿主。Service.Dispose取消自己的活动、可重复调用，不删除数据。分发器另有自身释放规则，宿主必须显式处理两者，不能以关闭UI代替释放整个宿主。
