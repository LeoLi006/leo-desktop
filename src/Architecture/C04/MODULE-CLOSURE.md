# C04-G2：普通模块接入闭环验收与收尾

日期：2026-10-21；核对基线为55d5029。本批只扩充隔离夹具和开发说明，没有修改生产业务或入口执行逻辑。

## 阶段结论

可信、编译进宿主的普通模块，可复用现有限定服务、能力注册、纯数据入口目录和真实渲染器。搜索、快捷栏、菜单不再需要针对每个新贡献模块添加业务分支；显示隐藏与能力停用分开，旧点击重新核验当前身份。

本结论只完成C04-G2的内部普通模块子集。新模块仍由宿主明确组装，服务及数据需要宿主绑定；独立代码包安装、兼容协商、进程隔离和通用复杂窗口并未交付。C04、C05、R01完整目标保持未勾选，不因本例通过而扩展权限。

## 可重复的接入顺序

现成实现：[限定服务与模块](ScopedNotesExample.cs)、[真实控件联合夹具](../../ModuleEntryClosureTests.cs)、[统一目录](../../ModuleEntryContributions.cs)。联合夹具中的Peer仅用于第二个身份的对照，不是生产模块或另一套业务执行器。

1. 宿主创建单一数据源与限定配置读取器，构造ScopedNotesExampleServices。模块仅拿IExampleNotesServices，不持有Preferences、数据路径、Form或任意动作分发器。
2. 构造ScopedNotesExampleModule并调用既有Registry.Register；注册时校验模块/动作契约，读取贡献时校验入口命名空间与动作归属。
3. 宿主把Preferences与自己的注册表、分发器连接：EntryContributions.Bind(prefs, registry, dispatcher)。该连接由宿主维护，不交给模块；每次Register并不自动替宿主完成所有生命周期动作。
4. 调用现有launcher.RefreshModules更新按钮和搜索；右键菜单打开时读取当前目录。提供者名称、图标、简称或启用状态变化，同样需要宿主触发刷新，本批不增加后台轮询或自动变更发现。
5. EntryDisplayModes覆盖提供者缺省模式；配置草稿通过BindReadOnlyView连接只读目录，不获得执行器。保存草稿不等于应用到活动配置，仍走原设置应用路径。
6. 停用：更新限定配置，调用CancelDisabled，刷新入口。需要停止的其他后台活动由各自所有者停止；关闭入口不能被解释为自动撤销已经发生的操作。
7. 移除：Registry.Unregister校验同一实例 → CancelDisabled → 显式Dispose宿主拥有的服务 → RefreshModules。服务/窗口资源仍由宿主释放；仅移除注册不宣称完成物理卸载。个人数据不因移除删除，显示偏好保留。
