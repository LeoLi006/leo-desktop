# C04 第五批：聊天与剪贴板窗口

## 固定目标与兼容

`leo-host-presentation/1` 追加 Chat 和 Clipboard，旧目标编号保持不变。对应反馈归属分别为 conversation 与 clipboard。请求不接受正文、路径、会话句柄、语音数据或额外视图参数。

- 正式 ConversationHost 的 chat_open 使用固定窗口端口；原构造、Standalone 与会话内部UI调度保持兼容。宿主关闭后拒绝新打开请求。
- 原 ShowChat 与语音入口先经过 chat_open 统一执行，显示仍使用 ShowChatCore 的原位置、焦点和非置顶设置。语音入口在打开完成后再次核验窗口代次，避免旧请求触发新窗口的录音。
- ClipboardCapability 只为 clipboard_open 增加可选窗口端口，其他数据操作仍在原UI和本地服务执行。正式 ClipboardClient 的窗口结果使用同一结构化反馈服务，正常成功保持静默。
- 聊天会话、流式回复、语音作业、私有句柄和模型工具权限不改动。剪贴板正文仍只在原本地窗口管理，不因窗口接入提供给模型。

## 生命周期

聊天完成关闭或Dispose时失效窗口代次，继续由原 ChatForm.ReleaseChat 取消回复、解绑语音事件并释放会话；ConversationHost 销毁同时阻止排队打开。

剪贴板窗口完成关闭时仅失效窗口代次，不释放历史服务或停止监听。“记录历史”是采集开关，不是历史窗口开关：

1. 开关变化时，服务沿用原监听启停并发出无正文的状态变化，宿主使旧打开请求失效。
2. 关闭采集后仍可打开已有历史和收藏；不删除数据、不清空收藏。
3. 重新启用不重复挂接监听。仅窗口关闭不产生采集开关变化。
4. 历史服务Dispose后使旧反馈和打开请求失效，同时沿用原监听释放和隐私事件解绑。

状态事件不保存业务正文、不新增计时器或线程；外层窗口服务仍在UI投递处复核取消、代次和宿主状态。

## 定向验证

锁定构建零警告。窗口专项104项及直接相关132项通过：聊天/语音41、音乐/剪贴板54、提醒宿主37，合计236项。

覆盖九个已接入窗口的直接影响、真实预览宿主聊天和剪贴板的打开/Esc关闭、已注册窗口动作回执、关闭后的旧请求、会话宿主销毁、采集关闭但历史窗口可用、历史服务销毁后的旧反馈、窗口关闭后模拟采集继续、停止及重新启用采集不重复挂接。

聊天流式与识别使用原模拟接口和语音夹具，剪贴板内容使用隔离数据与模拟采集回调；预览窗口不进行麦克风采集或本地识别解码。未读取真实剪贴板正文、调用真实Key或启动外部客户端。采集基础设施沿用的系统序号检查不是正文读取。
