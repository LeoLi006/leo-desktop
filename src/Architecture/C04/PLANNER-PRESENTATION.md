# C04 第四批：清单与便签窗口

## 接入目标

固定窗口目标新增 Todos、Notes、QuickNote，仍使用 `leo-host-presentation/1`，不改变旧四目标的编号。目标代次数组按枚举初始化，不为新模块复制调度器。

| 目标 | 现有入口 | 参数及宿主动作 |
| --- | --- | --- |
| Todos | todos_open、原脚下按钮/菜单/聊天回调 | View 为 day/week/空；空保留原视图。原日期意图通过宿主兼容数据转交原 TodoForm.Apply。 |
| Notes | notes_open、便签入口 | Query 为原便签草稿文字，最多20000字符；不是新增搜索协议。原便签搜索与置顶继续由原窗口处理。 |
| QuickNote | note_quick_open、速记快捷键 | 不接受外来草稿或清单参数；使用原输入焦点及Enter/Esc。 |

其他目标拒绝清单 View 或意图，清单拒绝非清单意图。模块持有固定窗口端口；兼容意图是纯数据，不能携带控件或回调。日期定位、周清单、位置记忆、未保存草稿确认和主题均由原宿主窗口处理。

## 关闭与取消

清单及两类便签窗口完成关闭时失效自身代次，排队旧窗口请求和旧反馈丢弃。便签取消关闭、窗口仍可见时不使其失效。宿主销毁沿用同一窗口调度取消与释放行为。

TodoCapability 只为 todos_open 增加可选异步窗口适配口，原构造保留兼容。该入口在排队前捕获窗口代次；原数据动作继续使用原UI执行、去重回执、保存及提交规则。不会因清单窗口关闭而取消提醒调度或已保存事项。

原宿主 ShowTodos 将视图请求交给服务，窗口核心仍使用同一 TodoForm。兼容日期意图若在排队时被取消，不会执行其中的旧编辑动作；服务不重试或重放该意图。

## 结构化反馈与速记提交

便签入口的反馈改用同一结构化 ActionResult 服务，正常打开继续静默，取消不报错。速记保存取得已完成 note_save 的回执，不添加第二次保存。

关闭速记时先失效旧窗口请求；仅当已有成功提交回执且 DialogResult 为 OK，才以新反馈代次保留原“已记下”普通确认。这不是重放关闭前的回调。取消或失败不会生成成功确认，原保存失败保留草稿行为不变。清单和便签的数据、JSON格式和提醒归属没有迁移。
