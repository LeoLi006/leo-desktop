# C04 第二批：客户端宿主服务

## 契约

`leo-host-client/1` 是内部服务格式，覆盖 Clash、音乐、媒体，不是外部模块包或跨进程协议。服务接口不暴露 Preferences、任意模块编号、路径、启动参数或 Key。

| 方法 | 边界 |
| --- | --- |
| ReadConfiguration | 只返回 Module、Enabled、Generation；正式宿主 Generation 继续使用原配置哈希。 |
| ReadDependencies | 复制并返回原有被动摘要，不启动客户端、不扫描设备、不调用网络或路径修复。 |
| ClientAvailable | 仅在原模型工具可用性检查位置调用原判断；不混入被动摘要读取。 |
| RecordFault | 模块固定，阶段枚举与异常类型；沿用上一批三字段、128条有界内存格式。 |

ClientHostContext 在构造时保存原配置代次，每次读取校验模块归属，统一记录配置、依赖或执行阶段的异常。服务自身失败保留原异常；记录器失败不覆盖业务结果；正常取消和配置变化不记为故障。

## 原行为保留

- Clash：原冷启动、等待、队列、显式开关与状态回读确认不变。模型能力继续使用原被动路径可用性判断，依赖描述仍为 unknown。
- 音乐：原实际歌曲候选、搜索发布、点歌队列、暂停/歌词/客户端启动和历史保存不变。被动依赖只读取已有候选与历史；模型工具可用性判断仍在原位置。
- 媒体：原媒体会话快照、播放器启动、控制回执及实际状态确认不变；被动摘要只看已有媒体状态，不主动枚举系统会话。
- 原构造参数通过默认服务适配，保留旧测试与调用方式。正式宿主显式注入服务和注册表所属的共享 ClientFaults；未提供记录器的兼容调用不新增日志存储。
- 三类能力通过同一上下文包装原执行方法，不另造动作策略。原取消、重复请求合并、客户端资源队列、超时与证据等级保持不变。

## 接入样例与限制

[编译样例](MinimalClientServices.cs) 演示如何在宿主创建限定服务。服务是架构边界，不是同进程安全沙箱；本批不迁移其他模块，不自动安装依赖或插件。

正式客户端服务记录与应用服务记录各有一个注册表所属的128条内存队列，不保存异常消息、堆栈、路径、配置哈希或业务正文，不产生普通通知或新后台线程。
