# C04-G2：入口贡献接入现有渲染器

## 范围与行为

本批接续[元数据试点](MODULE-ENTRIES.md)，把现有应用搜索、顶部快捷栏和“应用与媒体 → 模块入口”菜单接入同一目录。普通模块只需实现 IModuleEntryContributor 并由宿主显式注册，不新增集中业务分支。生产宿主仍不注册样例，不给个人配置添加模块。

旧本机应用、内置按钮与菜单来源不变；原排序、收藏、简称、显示模式和模块开关继续适用。贡献按钮参与已有排序与溢出菜单，搜索支持提供者简称及用户简称。综合设置的配置草稿只连接只读注册目录，不绑定动作执行器，保存前不会应用显示选择。模块图标沿用本机图标读取，无图标时绘制已有字形，控件销毁释放图片。没有新增周期任务。

显示设置接受 module/entry 命名空间；未覆盖时保留提供者默认模式。快捷按钮管理只调整入口位置，不把模块误当作可执行程序编辑。目录读取只遍历已注册贡献者，未注册提供者时保持空目录。

## 执行与边界

三个渲染器仅携带入口身份与来源，经当前注册身份校验，重新读取参数并交给原结构化执行器。移除、停用后的缓存按钮、菜单和搜索目标均不能退回文件路径启动。刷新模块时，同步清理已显示搜索结果；执行时仍再次校验，不能以界面缓存作为授权。

模块搜索目标从 FileApplications 和模型应用候选中过滤，不自动扩大模型工具。搜索显示不等于允许模型执行。模块提供者仍为宿主显式装配的可信编译对象，本批不实现任意代码导入、动态安装或沙箱。

## 隔离真实控件验证

`--module-entry-rendering-test <报告绝对路径>`：显式注册限定便签样例，验证真实快捷按钮、搜索简称与回车、菜单动作、设置字段、隐藏/停用、重新启用、移除后的缓存点击与搜索目标、无模型目录扩张和查询不写便签。样例使用内存便签，预览关闭释放服务，不写用户配置。

真实控件20项、原模块入口27项、入口一致性25项、入口显示兼容109项，共181项通过，锁定构建零警告。另运行原模块入口、入口一致性、入口显示兼容专项；只验证本批入口及直接相关链路，不重跑音乐、足球等业务专项。报告保存在忽略的 `.build/module-entry-rendering`。不使用真实 Key、网络、外部应用或个人数据。

本批有实际渲染行为变化，因此本地提交后统一更新一次 Leo；不制作发布包、不更新 GitHub 发布材料、不上传。
