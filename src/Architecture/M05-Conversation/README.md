# M05 第五批：聊天与语音执行迁移

日期：2026-10-20。保留现有窗口、中转站设置、聊天记录形状、Chat/Responses 协议和 SenseVoice；不新增聊天或语音功能。

## 注册与数据边界

`ConversationCapability` 提供会话执行、关闭和语音操作。宿主只有一个注册模块，窗口附着自己的 `ConversationSession`，关闭后移除。独立预览也使用同一种实现。

| 动作 | 执行与证据 |
| --- | --- |
| chat_open | 打开原聊天窗口，window-shown |
| chat_reply | 执行本轮流式任务，完成后返回私有 ChatReply，completed |
| chat_cancel | 撤销本轮回调资格、取消等待并停止语音，accepted |
| chat_close | 取消本窗口任务、释放语音并移除会话，released |
| voice_start / voice_finish | 开始录音、结束录音进入原转写流程，accepted |
| voice_stop / voice_stop_listening / voice_stop_speaking | 停止原录音、转写等待或朗读，accepted |
| voice_accept | 核验录音代次，一次性接受识别回执，snapshot |
| voice_speak | 通过私有任务提交原朗读内容，accepted 控制语义；回执不代表用户已听完 |

普通会话请求只携带随机会话/任务句柄，识别确认只携带会话编号和代次。Key、提示词、模型上下文和朗读正文不会编码进动作参数。任务内容只存在本机内存，结果标记为私有，通用诊断历史省略正文。接口异常转换为不含提供者正文的错误，保留 HTTP 状态、网络故障和用量限制的必要提示。

内部操作不提供给模型，`brain-*` 来源不能直接调用；只公开原有聊天窗口入口。结构化外部请求不接受内部会话句柄、音频或 Key。

窗口仍负责展示、草稿、上下文组装和后端委托；ChatApi/ChatAgent 继续作为提供者，未重写协议解析或更换模型。此为进程内窗口服务接口，不将委托和临时句柄包装成可导出的第三方模块协议。

## 流式任务与关闭

- 每窗口同时一轮回复，重复点击不另发请求。流式片段和工具状态同时检查本轮代次、取消状态和活动状态；已经入队的界面回调在执行时再检查。
- 停止后撤销旧任务的回调资格；旧提供者即使晚返回，也不能覆盖新回复、展示旧计划或追加重复片段。完成后的迟到片段也被丢弃。
- 工具活动先在会话中登记，再投递界面。失败时即使状态更新尚未显示，也不会误判为没有工具操作而自动重放。原重试按钮、工具操作后先核对、工具不兼容时文字重试的习惯保留。
- 保留窗口90秒期限和原 Q5 预算。分发器为会话设置有界期限，不自动增加模型重试轮次。
- 忽略取消的提供者在实际退出前继续占用有界任务槽：最多8个附着会话、16项任务。客户端停止等待不会把尚未退出的任务当作已释放，从而无限启动请求；完成后释放。
- 关闭/直接释放窗口均取消会话、解绑事件、释放设备菜单和语音资源。宿主先退出时，窗口使用内部幂等清理作为关闭回退。
- 原聊天历史列表改用已有原子写入，文件格式不变；保存失败仍保留本次内存会话。没有改动用量账本与收费统计逻辑。

## 本地语音

`ISpeechIO` 是宿主内部适配接口，生产实现仍是原 NAudio + SenseVoice INT8 / sherpa-onnx，CPU线程数和模型目录不变；Windows 朗读也沿用原实现。

识别结果与状态明确携带录音代次，界面队列不能把旧识别冒充成新录音。一次识别只接受一份回执；停止、重新录音和窗口关闭后，旧文字不能再填入草稿或自动提交。低置信文字仍进入原草稿流程。

录音停止、缓冲读取与转写状态转换使用同一音频锁；静音自动结束任务绑定原录音代次，不会结束后来开始的录音。取消后旧原生转写可能仍在完成当前 ONNX 调用，但不会发布结果；识别器释放在后台等待其原有锁，不阻塞关闭窗口。

文字与语音使用原本地路由及统一动作入口，明确口令不调用模型。语音产生的模型请求保留 voice 来源，继续通过 Q5 最多4步、实际目标校验及宿主预览确认；不因为语音输入而跳过确认。SenseVoice 识别质量和声学设置未改变。
