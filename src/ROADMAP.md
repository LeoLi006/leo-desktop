# Leo 桌面控制中心路线图

> 基线版本：v1.00.0
>
> 整理日期：2026-10-19
>
> 产品目标：用户按需求装配能力，通过一个桌面入口管理应用、信息与日常动作。

本文是后续开发清单。除“已有基础”外，未勾选内容均为规划，不表示已经实现。阶段按完成条件推进，不预设发布日期。

## 1. 产品原则

- 桌宠陪伴、效率桌面、极客控制、看球娱乐均可独立成立，用户可混搭。
- 常见明确操作优先本地执行；复杂意图理解与协调按需使用模型。
- 功能可以安装、启停与移除，入口可以单独显示或隐藏。
- 皮肤负责外观，使用方案负责能力搭配，场景动作负责临时执行。
- 重要操作有清楚的结果、失败原因与恢复入口。
- 个人数据留在本机，分享包与发布包只包含明确选择的内容。

## 4. 阶段 A：让用户搭建自己的 Leo

**目标：完成“使用方案＋能力中心”，建立可装配产品的基础。**

### A1. 使用方案

- [ ] 定义方案格式，保存模块选择、入口布局、快捷键和相关设置。
- [ ] 提供桌宠陪伴、效率桌面、极客控制、看球娱乐四种起始模板。
- [ ] 允许混搭、另存为、重命名、删除与重置自己的方案。
- [ ] 切换前展示将开启、停用或改变的项目，不擅自卸载软件、关闭代理或停止媒体。
- [ ] 切换失败时保留原方案，提供可理解的失败原因。
- [ ] 支持方案导入与导出；API Key、聊天、剪贴板和个人记录默认排除。
- [ ] 对目标电脑缺少的软件、模块或皮肤给出匹配与处理入口。

### A2. 能力中心

- [ ] 将内置模块、自定义应用、JSON扩展和ZIP扩展归入统一列表。
- [ ] 每项说明能力、入口、依赖、版本、状态及是否联网或使用模型。
- [ ] 统一安装、配置、启停、更新、移除与数据保留规则。
- [ ] 展示依赖缺失、快捷键冲突和配置异常，提供对应处理入口。
- [ ] 模块停用时释放其定时器、监听、后台任务和不再需要的窗口。
- [ ] 将S01、S02、S03纳入本阶段，避免再建立一套平行设置。

### 阶段 A 验收场景

- [ ] 新用户选择“桌宠陪伴”，可以不填写API、不配置外部软件直接使用。
- [ ] 陪伴方案不自动进行应用索引、足球刷新、剪贴板监听或麦克风采集；用户主动开启的能力单独说明。
- [ ] 用户混合开启足球和终端，保存自己的方案，重启后恢复。
- [ ] 停用、隐藏、移除含义明确，已有清单、便签和应用数据不丢失。
- [ ] 在另一台电脑导入方案时，不直接执行原电脑路径里的程序。

## 5. 阶段 B：成为统一操作入口

**目标：从“找应用”发展为“找内容、选动作、看结果”。**

- [ ] 为应用、文件、网址、功能指令和场景动作建立统一候选结构。
- [ ] 根据输入展示对应候选，并标明将执行的动作和目标。
- [ ] 输入存在歧义时提供候选选择，不猜测后直接执行。
- [ ] 支持当前输入、当前Leo窗口、当前播放器等可选上下文。
- [ ] 允许用户查看和关闭本次使用的上下文；读取选中文字等内容需主动触发或明确开启。
- [ ] 支持对解析结果进行纠正，例如修改待办日期、目标播放器或打开方式。
- [ ] 在同一入口查看正在执行、成功、失败、取消与重试状态。
- [ ] 整合S04、S05、S06、S07和S11，形成一致操作习惯。

### 阶段 B 验收场景

- [ ] 输入应用名、目录、时间安排与组合名称时，候选类型清楚且键盘可操作。
- [ ] “暂停”能显示控制哪个播放器，用户可纠正目标。
- [ ] 在已查询的比赛上执行“加入计划”，能确认关联的是哪场比赛。
- [ ] 本地明确指令在断网、未配API或达到API上限时仍可使用。
- [ ] 切换上下文后不会误用上一份文件、上一场比赛或上一个播放器。

## 6. 阶段 C：协调多步任务

**目标：让现有组合动作发展为可解释、可取消、可恢复的流程。**

- [ ] 定义统一步骤结果：成功、失败、跳过、取消及可供下一步使用的数据。
- [ ] 增加条件，例如“代理未开启才开启”。
- [ ] 增加等待条件，例如“播放器就绪后再播放”。
- [ ] 增加失败处理：停止、重试、跳过或使用替代步骤。
- [ ] 支持运行参数，例如每次执行前选择文件、目录或观赛网址。
- [ ] 提供可视化流程编辑、执行预览与逐步状态。
- [ ] 支持快捷键、定时触发，之后再扩展应用启动等事件触发。
- [ ] 处理重复触发、并发冲突、取消和超时，避免重复启动或重复修改状态。
- [ ] 对文件覆盖、删除及系统设置变更提供清楚的预览和必要确认。
- [ ] 保存可清理的本地执行记录，并连接S08统一撤销。

### 阶段 C 验收场景

- [ ] “准备看球”能按用户配置处理代理、观赛网址和音乐；已满足的步骤可跳过。
- [ ] 某一步失败时，用户知道失败位置、已产生的效果以及下一步选择。
- [ ] 取消后不继续执行剩余步骤，不假称已撤销已经完成的操作。
- [ ] 连续触发同一流程时，不重复启动软件或重复添加清单。
- [ ] AI可建议或填写流程，但执行仍遵循同一动作接口和确认规则。

## 7. 阶段 D：可选的桌面面板与扩展生态

**目标：服务更重度的桌面管理需求，保持纯桌宠方案轻量。**

### D1. 可选桌面面板

- [ ] 提供卡片式面板：今日安排、便签、当前媒体、下一场比赛、常用位置和流程状态。
- [ ] 卡片可选择、排序、隐藏，布局随使用方案保存。
- [ ] 面板可完全关闭，关闭后释放不需要的刷新任务。
- [ ] 增加便签与待办回链，从任务可查看原始记录。
- [ ] 整合S09和S12，支持内容整理与后台活动查看。

### D2. 扩展分发与兼容

- [ ] 明确模块API版本、兼容范围、依赖和升级迁移规则。
- [ ] 为模块提供最小示例、开发说明与独立验证工具。
- [ ] 支持更新前备份配置、更新失败恢复及指定版本回退。
- [ ] 明确哪些权限能由宿主约束；无法隔离的独立程序说明其信任要求，权限声明不等于系统沙箱。
- [ ] 先完善本地包安装体验，再评估在线模块目录、来源验证、维护和审核成本。
- [ ] 为使用方案、皮肤包和模块包分别规定分享内容，避免夹带个人配置。

## 10. 暂缓事项

这些方向可以评估，但当前不排入近期目标：

- 完整替换Windows桌面外壳、任务栏或资源管理器。
- 无确认地执行任意系统命令、删除文件或修改系统状态。
- 在模块基础尚未稳定时建设大型在线市场。
- 默认采集所有窗口、屏幕、剪贴板或用户输入作为AI上下文。
- 默认开启全部模块，或依靠持续模型调用维持基础桌面操作。
